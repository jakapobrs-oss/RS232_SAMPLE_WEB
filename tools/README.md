# tools/ — สคริปต์เทสโปรโตคอล RS232 (เฟส 1, แยกตามรุ่น/ยี่ห้อ)

สคริปต์ในโฟลเดอร์นี้ใช้ **พิสูจน์ว่า "สาย RS232-to-USB + ทีวี + โปรโตคอล" ทำงานจริง**
โดยยังไม่เกี่ยวกับแอป/เว็บเลย — ยิงคำสั่งจาก notebook ตรงๆ ผ่าน PowerShell ที่มีในเครื่อง
ใช้เป็นด่านแรกก่อนไปเทสบนแอป ถ้าด่านนี้ผ่าน แปลว่าฮาร์ดแวร์+โปรโตคอลโอเค

## สคริปต์ที่มีตอนนี้

| ไฟล์ | ยี่ห้อ/รุ่น | สถานะ |
|---|---|---|
| `Test-LgTv.ps1` | LG (โปรโตคอล LG RS232 มาตรฐาน) | ✅ ใช้งานได้ |

> รุ่น/ยี่ห้ออื่นๆ จะทยอยเพิ่มที่นี่ — ดูวิธีเพิ่มด้านล่าง

## วิธีเพิ่ม tester รุ่นใหม่

1. ตั้งชื่อตาม convention: **`Test-<ยี่ห้อ>Tv.ps1`** เช่น `Test-SamsungTv.ps1`, `Test-SonyTv.ps1`
2. คงรูปแบบพารามิเตอร์เดิมไว้ให้เหมือนกันทุกตัว (เรียกใช้ได้แบบเดียวกัน):
   ```powershell
   param(
       [string]$Port,        # ระบุ COM port เอง (ไม่ใส่ = หาให้อัตโนมัติ)
       [int]$Baud = 9600,    # ความเร็วพอร์ต (LG=9600, รุ่นอื่นอาจต่าง)
       [string]$Command,     # ส่งคำสั่งเดียว (ไม่ใส่ = เทสถามสถานะอย่างเดียว ไม่เปลี่ยนอะไรบนทีวี)
       [int]$TimeoutMs = 2000
   )
   ```
3. ส่วนที่มักต้องแก้ต่างกันในแต่ละยี่ห้อ:
   - **รูปแบบคำสั่ง** — LG ใช้ `[cmd] [SetID hex] [Data hex] + CR` (เช่น `ka 01 FF`); ยี่ห้ออื่นรูปแบบต่างกัน (Samsung ใช้ checksum/hex frame, Sony ใช้ control byte ฯลฯ)
   - **baud rate / พารามิเตอร์พอร์ต** — ค่ามาตรฐาน 9600/8/N/1 แต่บางรุ่นต่าง
   - **การ parse คำตอบ** — LG ตอบ `OK[data]x` / `NG[data]x`
4. ส่วนที่ **ใช้ซ้ำได้** จากตัว LG: การหา COM port อัตโนมัติ (`Find-SerialPort` — กรอง CH340/FTDI/Prolific/CP210x), การเปิด/ปิดพอร์ต, การพิมพ์ผลลัพธ์

## หมายเหตุโปรโตคอล LG (อ้างอิงเร็ว)

- พอร์ต: **9600 bps, 8 data bits, no parity, 1 stop bit, no flow control**
- คำสั่ง: `[cmd] [SetID] [Data]` + Enter เช่น `ka 01 FF`
- คำสั่งบ่อย: `ka` power (01=on / 00=off / FF=ถามสถานะ) · `kf` volume (00–64 hex) · `ke` mute · `xb` input · `mc` ยิงปุ่มรีโมต
- ทีวีตอบ: `a 01 OK01x` = สำเร็จ / `... NG...x` = ทีวีไม่รับคำสั่งนั้น
